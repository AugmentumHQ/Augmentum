## 3. Request parameters (verbatim — official reference)

| `temperature` | number | — | 1.0 | 0.0–2.0 ("0 guarantees the same response every time") |

| `stream` | boolean | — | — | SSE; **if `True` then `n` must be 1**; **must be `False` if `tools` specified** |
| `stop` | string/array | — | — | each sequence up to 64K, may contain `\n` |
| `response_format` | object | — | — | `{ "type": "json_object" }` activates JSON mode |

## 6b. Known drift / gaps

- 🟡 **Output cap** — Jamba hard-limits `max_tokens` to **4096**; profile `max_output=0` (unmodeled) → Coder budget logic could request more than the API allows. Fix: `max_output=4096` on the `ai21` profile.
- 🟡 **Stream ⊕ tools** — Jamba requires `stream=false` when `tools` present. If Augmentum streams tool turns to AI21 it will fail. Verify the request path forces non-stream for AI21 tool calls.
- 🟢 **JSON mode only** — docs show `response_format: {type:"json_object"}` (JSON mode); no `json_schema`. Profile inherits `supports_response_format_json_schema=True` → sending `json_schema` may be unsupported. Confirm/demote.
