# Model download checksum pins.
#
# Lists every external model file curl'd into the Augmentum container
# images at build time. Each entry pins the URL to a sha256 hash so a
# build with VERIFY_MODEL_HASHES=1 (the production CI build) refuses
# to ship if upstream has replaced the bytes since the pin was set.
#
# Why this matters: the curl commands in Dockerfile / Dockerfile.gpu
# pull ~500 MB of ONNX weights from huggingface.co and github.com
# release artifacts. Both are TLS-secured, but a publisher-account
# compromise or a same-tag re-publish (which github releases technically
# allow) would silently swap the bytes that land in our image.
# Hash-pinning closes that.
#
# Format: <sha256>  <file>  <url>
# Empty hashes (`<UNPINNED>`) are placeholders — Dockerfile builds with
# VERIFY_MODEL_HASHES=1 fail until they're populated. Populate by
# running:  scripts/populate_model_checksums.sh
#
# When upstream legitimately bumps (e.g. a new Kokoro release), update
# the URL and re-run the script. The diff is the audit trail.

# ── WeSpeaker (~28 MB) ──────────────────────────────────────────────
<UNPINNED>  voxceleb_resnet34_LM.onnx  https://huggingface.co/openspeech/wespeaker-models/resolve/main/voxceleb_resnet34_LM.onnx

# ── DTLN speech-enhancement (~3.7 MB) ───────────────────────────────
<UNPINNED>  dtln/model_1.onnx  https://raw.githubusercontent.com/breizhn/DTLN/master/pretrained_model/model_1.onnx
<UNPINNED>  dtln/model_2.onnx  https://raw.githubusercontent.com/breizhn/DTLN/master/pretrained_model/model_2.onnx

# ── Kokoro TTS models — pinned to release v1.0 (~120 MB total) ──────

<UNPINNED>  voices-v1.0.bin        https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/voices-v1.0.bin
<UNPINNED>  kokoro-v1.0.fp16.onnx  https://github.com/thewh1teagle/kokoro-onnx/releases/download/model-files-v1.0/kokoro-v1.0.fp16.onnx

# ── Google Chrome stable .deb (~150 MB) ─────────────────────────────
# Used by the App Builder verify step (headless browser).
# This intentionally floats — Chrome ships security patches frequently
# and stale pins are worse than no pins for browser engines.
# Pinning gets a build-arg opt-in (CHROME_DEB_SHA256) for orgs that
# need reproducibility over freshness.
<FLOATING>  google-chrome-stable_current_amd64.deb  https://dl.google.com/linux/direct/google-chrome-stable_current_amd64.deb
